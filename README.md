# 票务自助机 · 纸卷补给与退款核验平台

面向票务自助机网络的运营平台：管理终端、纸卷批次、票据号段、收款订单、故障工单、补给路线与退款凭证。
**支付、出票均为进程内模拟适配器；订单与金额全部为模拟数据。** 零第三方依赖，仅需 Node.js ≥ 22（内置 `node:sqlite`）。

## 一条命令启动（含演示数据）

```bash
npm run demo          # 创建 SQLite + 出票/卡纸/退款演示数据并启动
# 打开 http://127.0.0.1:8080
```

其他命令：

```bash
npm start             # 不带演示数据启动（沿用 data/platform.db）
npm test              # 10 项规则测试（内存 SQLite，不落盘）
rm -rf data && npm run demo   # 重建演示数据
```

环境变量：`TKP_PORT`（默认 8080）、`TKP_HOST`（默认 127.0.0.1）、`TKP_DATA_DIR`（默认 ./data）。

## 演示数据包含

- T-001 / T-005 正常连续出票；T-003 **卡纸**（票号占用作废、停止发票、退款成功）；
- T-006 **断纸**（扣款成功未出票，退款待主管审批；可在补给路线中扫码换卷恢复）；
- T-004 **设备离线**扣款未出票 + 离线补传，退款渠道**超时**入复核；
- T-005 硬件重试导致**重复出票**；T-002 补给员上报**纸卷倒装**；
- 两条补给路线，任务分别处于排队 / 已锁定 / 柜门已开 / 异常中止状态。

## 核心业务规则

| 规则 | 实现 |
| --- | --- |
| 票据号段连续，不跳号 | 即时事务内条件更新 `next_no`，卡纸票号 `void_jam` 留痕；号段用尽即关闭并停用终端（`server/services/tickets.js`） |
| 纸卷并发扣减不超卖 | 同事务条件更新 `paper_remaining > 0`，纸张/号段任一不足即回滚并停用终端 |
| 订单幂等 | `client_request_id` UNIQUE 重放只返回原订单；支付侧另有幂等键，不会二次扣款 |
| 五类复核队列 | 扣款成功未出票 / 重复出票 / 退款超时 / 纸卷倒装 / 设备离线 |
| 退款一次一单 + 权限 | 原订单 UNIQUE；未真实扣款不可退；发起人不能自审（职责分离）；审批时快照纵向证据链 |
| 人工补票 | 必须关联未关闭的故障工单，票号仍走连续号段 |
| 补给任务锁定 | 条件 UPDATE 抢单，两名补给员同时领取只保留一个锁定者 |
| 扫码开柜 | 必须先锁定任务、扫码口令匹配才开柜；换卷前后各留存一张计数器"照片"（SVG） |
| 离线补传 | `client_event_id` UNIQUE 去重；顺号补登，错号进复核而非跳号 |

## 六个界面

1. **终端地图**：地图图钉 + 终端矩阵，纸量刻度（带刻度线）、在线状态点、停用/低纸量配色；
2. **纸卷库存**：批次入库、在库/装机/用完状态；
3. **补给路线**：领取锁定 → 扫码开柜 → 换卷完成 / 倒装上报，展示前后计数器照片；
4. **故障队列**：五类复核分组处理 + 故障工单派单、人工补票、修复恢复；
5. **订单核验**：模拟购票（可重放幂等键）、订单 支付→票据→回执→工单→退款 核验链；
6. **退款台账**：原订单 → 支付凭证 → 票据 → 设备回执 → 工单 → 处理动作的**纵向证据链**。

配色：靛蓝（主色）、浅灰（底）、亮黄（强调）。票据号段统一使用等宽字体。

## 存储

- `data/platform.db`：终端、号段、票据、订单、支付、工单、复核、退款、路线任务、离线事件（SQLite WAL）；
- `data/receipts/<终端>/<类型>/`：设备回执本地文件——计数器照片（SVG）、柜锁回执、打印小票、退款/离线 JSON 回执；
  通过白名单校验后的 `/files/...` 只读访问。

## 目录结构

```
server/
  db.js            SQLite schema + 轻量迁移
  adapters.js      进程内支付网关 / 打印机模拟
  receipts.js      设备回执本地文件（含计数器照片）
  services/        tickets 号段 · terminals 纸卷 · orders 购票
                   faults 工单复核 · refunds 退款 · routes 补给 · offline 补传
  seed.js          演示数据
  index.js         HTTP API + 静态资源
public/            六个视图的单页前端
test/run.js        规则测试
```
